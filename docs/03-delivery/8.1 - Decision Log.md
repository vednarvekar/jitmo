## Phase 2 step 1: Tier 0 memory check (8 Nov 2026)

The SP2 figure of 710MB included torch and transformers, which the `gliner` Python package imports. The model worker will use onnxruntime only (as SP1 did), so I measured that (Windows, int8 models, 1 thread, one session each, Python 3.12 with numpy, a stand-in for the Rust worker):

| Piece | Working set | Private | Note |
|---|---|---|---|
| Runtime baseline (Python, numpy, onnxruntime) | 54 MB | 31 MB | Smaller in Rust; not measured |
| Router (MiniLM int8) after load | 88 MB | 61 MB | about +35 MB over baseline |
| Extractor (GLiNER-small int8) after load | 248 MB | 221 MB | about +195 MB over baseline |
| Extractor after 20 inferences | 253 MB | 222 MB | Peak while loading 382 MB |

Both models in one worker should come to about 280 to 300MB. Add Core (14MB) and idle is about 300MB: PR1 is met only on the edge, with the worker loaded, and clearly met when the worker has exited (D27: 14MB). The 710MB number was a packaging artefact, not the model; my earlier note that idle would be about 0.8GB was wrong.

**Decision (recommended, D32):** keep the two-model worker lean (onnxruntime plus tokenizers, no torch), load the router first, load the extractor only when the rules cannot fill a slot, and let the worker exit after idle. Report PR1 as "under 300MB, worker unloaded; about 300MB with Tier 0 loaded". The "Phase 2 done when" wording (under 300MB with Tier 0 loaded) will not be met strictly, so either the worker idle-exit counts or PR1 becomes 350MB. Needs your call.

Separate risk: SP2 failed on accuracy (62% on a blind set), so extraction quality in Phase 2 comes from rules plus runtime gazetteers (contacts, apps, files), not the model. Not yet re-measured on the 8GB laptop; the numbers above are from a busy dev PC.

## Phase 2 steps 2 and 3: worker and real router (8 Nov 2026)

- **Worker process** (`jitmo-model-worker`): separate process, stdin/stdout JSON, exits after 300 s idle (setting), restarted by Core after a crash or hang (one retry, then "unavailable"). ONNX Runtime telemetry is switched off. The "no network" rule is by design only for now (no network code); the Job Object cap from D28 is not built.
- **Router in Rust** (MiniLM int8 + SP1 head, same chain-split rule): re-scored on the SP1 sets from Rust and it matches Python: single-task 104/112 (92.9%) on test and 97/120 (80.8%) on the fresh test2, about 2 ms per request. Chains and out-of-scope behave as in SP1 (chains about 60%).
- **Memory, measured with the real worker** (release exe, router loaded): **63 MB working set, 48 MB private**, 7 ms per request including the pipe, 27 MB exe (ONNX Runtime linked in). Lower than the Python estimate of about 90 MB. Extractor memory is still to add (about 195 MB if GLiNER is used).
- **Core uses it** when the worker program sits next to the app and `models/router/` exists; otherwise, or if the worker is down, it falls back to the rule-based router. Skills now carry a `task` label (A1, A3, M2) that maps the model's label to a skill. A model's best task that has no skill yet gets "I can't do that yet", never a lesser match.
- **Test set with the real worker** (`--worker`): the same 12 automated tests pass.
- **Not done in this step:** the GLiNER extractor. Slots still come from the skill example patterns; closed lists (apps, contacts, files) come with the resolver in step 4. Model files are not in git (`models/` is ignored); they are copied from the spikes for now and need a fetch script before the installer or CI can use them.

## Phase 2 step 4: resolver and context (8 Nov 2026)

- **Resolver** (`core::resolver`): follows each slot's `resolve` order. `selected_file` is used for "this" or nothing said; `named_file` is a fuzzy match (exact word, contained word, one typo) over Downloads, Documents and Desktop; `recent_download` is used for "the latest download" or when nothing is said or selected; `usual_*` reads the setting `usual.<type>` when nothing is said. A file now carries `name` and `path`, so `{file.path}` works and the WhatsApp skill is no longer refused before the confirm.
- **Ties (FR4):** files within 0.08 of the best score make one question with up to three options; dismissing it cancels. A name that matches nothing says "I couldn't find X." and never confirms or sends.
- **Context service** (`core::context`): bounded walk (depth 3, 20,000 files, skips `node_modules`, `.git`, `AppData`, partial downloads), nothing stored. Explorer's selection is read when the hotkey is pressed (`adapter-windows::explorer`, read-only, no keys or clicks sent) and kept as a snapshot.
- **Verified live (8 Nov):** the Explorer read passed its `--ignored` live test (new Explorer window with a file selected, read back by window handle). Not yet tried through the real hotkey path in the app. The snapshot arrives a few hundred ms after the hotkey, so a request sent in that moment sees no selection.
- **Still stand-ins:** contacts and apps pass the user's words through (`named_contact`, `named_app`); real contact resolution and an installed-apps list for slots are later. Usual choices are only read; writing them after a successful task (FR10) is step 7. The file index is rebuilt per request (fast enough for now; cache if it shows up in timings).

## Phase 2 step 5: connectors, batches a and b (8 Nov 2026)

- **5a `local_calc`** (Q1, Q4, Q5; also covers T98): percent and tip, arithmetic, unit conversions, next full or new moon (Meeus formulas, within 15 minutes of three published 2026 full moons), time in a city with daylight saving. Skills read the whole sentence through the built-in `{request}` slot; a step can return a `message`, which becomes the Done text. Sunrise and sunset need a location and are not built.
- **5b `files`** (F1 to F4): show in Explorer, list recent downloads (today, yesterday, this week), open, and move with Undo. A move never overwrites and Undo refuses if the original spot is taken. Which file or folder is meant is decided by the resolver first (new `named_folder` strategy); file-type words ("sheet", "deck", "pdfs") match the extension and time words ("from last week") are ignored.
- **Router rule added:** a best guess under 0.30 is declined instead of asking with three weak options (doc 07 says "ask" below 0.50; with more skills built, out-of-scope requests like T89 started producing a "Did you mean" question). Needs a real-log check.
- **Known gaps:** T26 "Move **these** PDFs" needs a multi-file selection, which is not built (selection is one file). Real connectors for file open and move were tested in temp folders, not on your real files.
- **5c reminders and timers** (R1, R2; also T99): the time parser handles "at 6pm", a bare "at 6" (next time the clock reads 6), "in 20 minutes", "a 10-minute timer", "1 hour 30 minutes", "tomorrow at 9am", weekdays, noon, 24-hour times; no time gives "When should I remind you?" and saves nothing. Reminders go in the existing `reminders` table; an app thread checks every 10 seconds and shows a Windows toast (PowerShell notification identity, text passed in environment variables and XML-escaped). A reminder missed while the app was closed fires at next start, marked as missed; a failed toast still marks it done so it cannot loop. Undo (10 s) deletes it. The toast call returned no error in a live test, but I cannot see your screen, so whether it appeared (Focus Assist, notification settings) is unconfirmed. No repeat reminders yet.
- **5d `system_controls`** (S1 volume and brightness, S2 lock, S3 Wi-Fi and Bluetooth, S5 screenshot): user words are parsed into a fixed operation and passed to fixed PowerShell scripts through environment variables, never pasted into a script (tested). **Read paths verified live on this PC:** Core Audio volume (44% unmuted), WMI brightness (83), WinRT radios (Wi-Fi On, Bluetooth On), lock-screen detection. **Setters not run live** (volume change, brightness change, radio on/off, lock, screenshot): they would change your PC, so they wait for your go-ahead. Radio and screenshot have Undo. Do Not Disturb (S4: T48, T63) is not built; it needs the SP7 UI Automation route. Known router gap: "louder" goes to media control (A3, 0.86) instead of S1 (T57 is a declared known gap).
- **Still to do in step 5:** `windows_system` S1 to S5 (these change the real PC, so no live runs without asking), `browser` (A4 to A6), `spotify` (A2, A3).
