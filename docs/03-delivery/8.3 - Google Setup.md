# 8.3 Google Workspace setup

What the owner does once so Jitmo can use Gmail, Google Calendar and Drive. The same mail, calendar and file skills run on Google: only what is behind the connectors changes. Microsoft stays in charge when it is set up; to prefer Google, save the setting `mail_provider` as `google`.

## 1. Create the project

1. Open console.cloud.google.com and create a project named `Jitmo`.
2. **APIs & Services → Library**: enable **Gmail API**, **Google Calendar API**, **Google Drive API** and **People API**.

## 2. Consent screen

1. **APIs & Services → OAuth consent screen** (or Google Auth Platform): user type **External**, app name `Jitmo`, your email as support and developer contact.
2. Add yourself under **Test users**, then **Publish app** ("In production"). A test-mode app signs you out every 7 days; an unverified published app used by its owner only shows a one-time "unverified app" warning.
3. Scopes Jitmo asks for (least privilege): `gmail.modify`, `gmail.send`, `calendar`, `drive.metadata.readonly`, `drive.file`, `contacts.readonly`, `contacts.other.readonly`.

## 3. Create the client

**Credentials → Create credentials → OAuth client ID → Desktop app.** Copy the **client id** (`…apps.googleusercontent.com`) and the **client secret** (`GOCSPX-…`). For an installed app Google says the secret is not confidential.

## 4. Tell Jitmo

```
set Google client id to 123456-abc.apps.googleusercontent.com and secret GOCSPX-xxxx
```

Restart Jitmo, then say `sign in to Google`. The refresh token is kept in Windows Credential Manager (`jitmo/google/refresh-token`); `sign out of Google` removes it.

## 5. Check it

`Any urgent emails?`, `emails`, `what's on my calendar today`, `email <exact name> that the report is ready` (shows the exact message, then sends after your yes). Names are matched exactly against your Google contacts; an unknown name is refused, not guessed.
