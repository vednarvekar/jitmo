# Product lens
Score: 4/10 | Vote: FUND IF

## What is strong
- Real experience idea: hotkey, type, it acts. Acting beats answering, and the brief says so.
- Idle at 14 MB with an on-demand helper that exits is a craft detail users feel (no slowdown on a busy PC).
- Safety is in plain code: confirmation before sending, Undo. That is trust built into the experience.
- Cheapest-first ladder means most requests need no model, so the product can feel instant.

## What would kill it (the top 3, most dangerous first)
1. **No one thing.** Apps, settings, files, reminders, music, calculator, lookups, WhatsApp, Outlook, Gmail, Teams. That is a list, not a product. The pitch needs a paragraph. Nothing here is brilliant yet, only broad.
2. **Misses will feel broken.** Router 81-92%, extractor about 63%, chains about 60%. An assistant that acts wrongly one time in three loses trust faster than one that does nothing. Measurements were not taken on the 8 GB target laptop.
3. **Seams everywhere.** WhatsApp stops at "user presses Send". Unsigned installer will meet SmartScreen warnings. Cloud integrations contradict the local-first story. Each handoff is where the first five minutes break.

## The questions I would ask the founder
- Describe the first five minutes for one named person. What do they type, what happens, and what makes them type a second time?
- Which single command must feel flawless? Would you ship only that?
- What does a failed or low-confidence request look like on screen? Is the recovery graceful?
- What do Windows search and Copilot already do for the same requests? Where is yours visibly better, in speed, privacy or reach?
- Who installs it, and what do they see when Windows warns about an unsigned app?
- How many of the 643 audit inputs would a real user actually type? (Open question: no user data exists.)

## If FUND IF: the conditions
1. Pick one customer and one sentence. Cut every skill not needed to deliver it.
2. Raise the chosen skill set to near-perfect on the 8 GB target laptop, with a measured number, before adding any skill.
3. Put five real users in front of it and watch the first five minutes unaided. Report what they typed that failed.
4. Fix the install path (signing route) so the first launch is clean.
5. Make failure honest: ask, show what it understood, never act on low confidence.
